# SUIsei — Design Bible & Roadmap

> **What this is.** The design bible for SUIsei: the locked decisions, the architecture, the public contracts an integrating engine depends on, the load-bearing pillars, and the work that remains. [`README.md`](README.md) is the front page (features + usage); this is the *why* and the *what's next*.
>
> **What SUIsei is.** A standalone, **GPU-free, NativeAOT-clean**, retained-mode, WinUI-3-inspired XAML UI runtime for .NET 10, plus a Roslyn XAML source generator. It knows nothing about any render graph: it produces a neutral draw list (or exposes its composition tree directly) and a host renders it. In the Loom engine it is consumed by the thin `Loom.UI.SUIsei` glue through Loom's neutral `IRenderContext.DrawList` verb — the same path Dear ImGui uses — so no UI type ever enters the engine's describe/execute layers.

## 1. Locked decisions

| Axis | Decision |
|---|---|
| Dialect | **WinUI 3** (`Microsoft.UI.Xaml`) syntax — a curated, published *subset* (§4). |
| Binding | **`{x:Bind}` only**, compiled. No reflection `{Binding}`. |
| Runtime | **NativeAOT-clean** end to end — no reflection in the property system, binding, layout, or hot paths. |
| Precompiler | **One Roslyn incremental source generator** consuming `.xaml` as `AdditionalFiles`; emits tree construction + typed `x:Bind`/event/storyboard/visual-state glue. No MSBuild task. |
| Text | **MSDF/MTSDF prebaked glyph atlases**; runtime shaping behind a swappable `ITextShaper`. |
| Composition | **Retained `Visual` tree** behind the element tree, rendered by a pluggable **`IUICompositor`** — the engine-portability seam. SUIsei's default `DrawListCompositor` flattens to neutral draw data. |
| Surfaces | Screen-space overlay **and** in-world (the in-world quad math lives in the *host glue*, keeping SUIsei purely 2D/neutral). |
| Colour / HDR | Authoring uses a float `HdrColor` (`0..1` = SDR/paper-white, `>1` = above paper-white, opt-in); composited as premultiplied **RGBA16F**, pinned to a configurable paper-white reference. |
| Hosting | `UIHost` is **per-window, not a singleton**; holds no engine handle. |
| Testability | **Headless-testable by construction** — every logic subsystem is unit-tested on CPU with no GPU/window. |

## 2. Architecture

**Two retained trees and a pluggable compositor.** The UI is a retained **element tree** (dependency properties / layout / controls) that drives a separate retained **composition `Visual` tree** (transform / clip / opacity / brush / content), which a pluggable **`IUICompositor`** turns into rendering. This is WinUI's element-tree-vs-composition-tree split, made into the portability seam:

- **The default `DrawListCompositor`** walks the visual tree, resolves transform/clip/opacity into a pre-transformed vertex + command stream, and **recomposites only dirty subtrees**. It produces a neutral `DrawListData`.
- **A foreign engine** implements its own `IUICompositor`, consumes the `Visual` tree directly, and maps it onto its own scene — taking the whole element/layout/input/animation half and substituting only the compositor. The `Visual` tree is the neutral contract one level above the draw list.

### The neutral draw-list contract (load-bearing)
SUIsei carries its own draw types in a `SUIsei.Drawing` namespace: `OverlayVertex` (position, uv, premultiplied HDR colour, custom params) and `DrawCommand` (clip rect, texture index, index range, a `uint` tag). **These two layouts are byte-identical to the host's structurally-equivalent types**, so the host glue zero-copy-casts (`MemoryMarshal.Cast`) rather than translating. `DrawListData` (the vertex/index/command spans + texture slot table + surface size + HDR flag + revision + texture revision + damage rect) is **SUIsei-private** — the painter unpacks its fields. **The frozen contract is the `OverlayVertex` + `DrawCommand` memory layout**; keep them in lockstep with the host's neutral types (no analyzer guards this today — see §7). Indices are 16-bit and relative to each command's `VertexOffset`, which the host passes as the base vertex: a surface past 65,535 vertices is split into index windows, so `VertexOffset` is not always 0 (a layer marker's `VertexOffset` is instead the absolute index of its tint vertex). The compositor double-buffers each surface's streams and hands out `DrawListData` as views over them, so a recomposite allocates nothing: a list stays readable through its surface's next recomposite and its streams throw once the one after that reuses its buffers. A host reads the current list each frame rather than keeping one.

**Primitive kinds.** A command's `Tag` is a `UIPrimKind`: `Fill` (0), `RoundedRect` (1), `Border` (2), `Glyph` (3), `Image` (4), the group-layer markers `BeginLayer` (5) and `EndLayer` (6), and `Vector` (7). A host fails loud on any other tag.
- **Antialiasing** is one rule for every analytic kind: a signed distance divided by the length of its screen-space gradient, `saturate(0.5 + d / max(length(float2(ddx d, ddy d)), 1e-6))` with `d` positive inside, a one-pixel ramp centred on the edge that is the same at every angle (`fwidth`'s `|ddx| + |ddy|` over-blurs by up to √2 at 45°). RoundedRect and Border apply it to their rounded-box SDF; their quads end at the rect, so only the inside half of the ramp is drawn.
- **`Vector`** draws tessellated geometry. `Custom` holds four signed distances `d0..d3` to the edges the triangle antialiases, positive inside, each linear across the triangle in any consistent unit; an unused one holds `VectorVertex.Unused` (1e6), constant across the triangle, so its zero gradient makes its factor 1. The colour is the vertex colour × the product of the four coverages × the command's texture sampled at `Uv` (slot 0, the white texel, for a solid colour). Derivatives are taken in the kind's uniform branch.
- **Group layers.** A `BeginLayer` marker's `ClipRect` (and its quad) is the bounds of what the layer draws, rounded out to whole pixels and clipped, not the clip it inherits, so a small faded group costs a small target; a layer nothing is drawn in is left out. A host renders the layer into a target over that rect and clips the layer's content to it.

**Texture slots.** A command's `TextureIndex` indexes its own list's slot table, `DrawListData.TextureSlots`, not any global id.
- **What a slot holds:** a `TextureSource`, a neutral description the host resolves: RGBA8 texels, a size, and a `Version` that moves when the texels change.
- **Slot 0** is always `TextureSource.White`, the white texel untextured commands sample.
- **The other slots** hold every source the list's glyph and image commands sample, each once, numbered densely in the order the walk first uses them. Glyph atlas pages are ordinary sources there, so a host always binds the atlas the glyphs were laid out against.
- **Every `TextureIndex` is in range:** each one the compositor emits is below its list's `TextureSlots.Count`. A host treats one outside it as a broken list and fails loud rather than sampling something else. Loom's painter refuses it, naming the command and surface; the CPU rasterizer skips and counts it.
- **`TextureRevision`** moves when the table names different sources or slots, or a source in it changes its `Version`. It also moves on a clean frame that re-submits the same list. A geometry-only recomposite leaves it alone, so a host rebinds and re-uploads only when it moves.
- **Cost:** slots are assigned with one reference-keyed lookup per primitive into retained storage, so a steady frame allocates nothing.

**Composition paint.** Content is painted by retained, neutral `CompositionBrush` objects named after WinUI's composition layer: `CompositionColorBrush`, `CompositionLinearGradientBrush` and `CompositionSurfaceBrush` (an image). `RectContent.Fill` / `BorderBrush`, `GlyphRunContent.Brush` and `ShapeContent.Fill` / `Stroke` hold them; an `Image` is a `RectContent` filled by a surface brush. Each XAML brush keeps one composition brush, shared by every content showing it, and updates it in place; a paint change advances the brush's own `Version`, not the content's, so a foreign compositor keying work on what a content draws reads both. `Visual.Dump()` describes paint.
- **Gradients are exact, with no ramp texture.** The compositor cuts the painted geometry wherever the colour stops being linear (each stop, each repeat of a wrapping gradient) and colours each piece's corners with the gradient's colour there; within a piece the colour is linear in position, which is what interpolating vertex colours produces. Rects are cut into bands that keep their part of the rect's 0..1 uv and its whole size in `Custom`, so the rounded-rect and border shading still finds the real edges; glyph quads are cut into pieces that keep their atlas uv. Vertex colours are premultiplied half floats, so stops above paper white survive. Interpolation is of premultiplied colours, as a GPU interpolates vertex colours: exact in linear light (`ScRgbLinearInterpolation`); in sRGB (`SRgbLinearInterpolation`, WinUI's default) each stop interval is cut into 8 pieces sampled exactly, within 0.006 in linear light between them (under one 8-bit sRGB step from mid-grey up, up to five near black on a full black→white step). An sRGB gradient with a stop above 1 throws when drawn, as sRGB interpolation is not defined there. Neighbouring pieces share bit-identical corners, so no seam pixel is drawn twice or missed. No new prim kind; the `OverlayVertex` / `DrawCommand` layouts are unchanged.
- **Image paint** fills a rectangle with square corners (the `Image` control, an `ImageBrush` background) as an `Image` quad, cut to the rectangle by narrowing its uv. On rounded corners, or as a border, the rectangle's outline (its border ring: the rectangle less the inner one, whose radius is the corner radius less the thickness) is filled through the `Vector` prim, sampling the image through its texture slot; a letterboxed image is clipped to its rect there. On text it throws `NotSupportedException`: a glyph samples the font atlas.
- **The rasterizer's fill rule** is the GPU's top-left rule: a pixel centre on an edge two triangles share (a quad's diagonal, a cut between gradient bands) belongs to exactly one of them, decided from each edge's canonical orientation.

### Dependency floor + satellite projects
The **core `SUIsei` runtime depends on `StbImageSharp` alone** (to decode baked atlas PNGs) — nothing else, no GPU, no engine. Heavier capabilities are **separate satellite projects** precisely to keep the core dependency-light and NAOT-clean:

| Project | Role | Wired into the host build? |
|---|---|---|
| `SUIsei` | core runtime (DP model, controls, layout, composition, routed events, focus, hit-test, animation, `FontAtlas`, `ITextShaper` seam, default `SimpleTextShaper`) | yes |
| `SUIsei.SourceGen` | Roslyn `IIncrementalGenerator` (`netstandard2.0`), ships as an analyzer | yes |
| `SUIsei.Tests` | headless unit + source-gen snapshot tests (TUnit + Shouldly), no GPU | yes |
| `SUIsei.Rasterizer` | a CPU software rasterizer — the byte-identical oracle for compositor/group-opacity tests | test-only |
| `SUIsei.HarfBuzz` | HarfBuzzSharp text shaper (an `ITextShaper`); native assets currently Win32-only | satellite |
| `SUIsei.Text` | a **native managed MTSDF atlas generator** + OpenType reader (glyf + CFF) + atlas baker | not yet wired |
| `SUIsei.Text.Tool` | build-time bake tool driving `SUIsei.Text` | not yet wired |
| `SUIsei.Gallery` | demo application | standalone |

### Text: atlas generation and shaping
Text is **glyph-id-keyed MTSDF**, generated natively and shaped behind a swappable seam — both halves chosen to stay cross-platform, dependency-light, and NativeAOT-clean.

- **Glyph-id atlas + two independent seams.** `FontAtlas` keys glyphs by glyph id (keeping a codepoint→gid `cmap` for the no-shaping fast path and caret math), because ligatures and contextual forms are glyph ids with no codepoint. An `ITextShaper` turns a text run into positioned glyph ids and resolves them through an `IGlyphSource` (codepoint/glyph-id → glyph + advances + metrics) rather than a concrete `FontAtlas`, so the **shaping backend and the imagery backend swap independently**: a non-MTSDF imagery source (a bitmap atlas) can satisfy `IGlyphSource`, and a platform shaper can satisfy `ITextShaper`. The default `SimpleTextShaper` reproduces advance-based codepoint layout; `SUIsei.HarfBuzz` (a separate project, to hold the core's dependency floor) provides a HarfBuzzSharp shaper. The baker enumerates **GSUB-reachable** glyphs (a lookup walk over Single/Multiple/Alternate/Ligature/Reverse + unwrapped Extension), not just the `cmap` set — Cascadia's programming ligatures are `calt` contextual 1→1 substitutions reachable only through GSUB, so glyph *count* is preserved (caret/cluster mapping stays one glyph per source char) but the rendered glyph ids never appear in `cmap`.
- **Native MTSDF generation (`SUIsei.Text`).** A managed, multi-threaded MTSDF atlas generator with a hand-rolled OpenType reader and a hand-rolled, zero-dependency RGBA8 PNG encoder — no external font library, no `msdf-atlas-gen`. The distance math is a faithful port of msdfgen (`edgeColoringSimple`, the bisector-gated per-channel perpendicular-distance selector, the cubic solver) in `double` precision, with the winding-aware **overlapping-contour combiner** that was the single biggest correctness fix: without it a glyph built from overlapping contours (a stem plus separate arm rectangles) carves false notches through solid strokes. A final true-distance pass corrects residual channel-medial-axis edges. RGB carry the per-channel signed pseudo-distance; **A is the plain true signed distance** — the channel SUIsei reserves for outline / glow / weight. TrueType `glyf` is the verified outline path; CFF/Type2 (the OTF cubic format) is implemented behind the same `IGlyphOutlineSource` seam but **OTF-untested** (no `.otf` fixture is available).
- **The FontAtlas drop-in contract.** The emitted JSON + page is a drop-in for the runtime `FontAtlas`: `unitsPerEm` and metrics from `head` / `OS/2` typo fields; distance math in y-up EM space (TrueType's native winding gives inside-positive directly, with a nonzero-rule safety net flipping an inverted font); `planeBounds` is the ink box expanded by `pxRange/2` and y-flipped; `atlasBounds` is the integer texel rect with **no half-texel offset**, so a cell-pixel centre maps exactly onto a sampled texel centre under the UI shader's bilinear footprint; the page is decoded linear/UNORM, never sRGB. This is internally self-consistent generation↔sampling, and therefore *not* byte-identical to `msdf-atlas-gen` (whose `atlasBounds` carry a `+0.5` offset) — the bar is "visually indistinguishable / drop-in", not byte-identical.

### Pillar: headless-testable by construction
`UIHost.Tick(...)`, `UIRoot.LayoutPass(...)`, and `UIRoot.Render()` run to completion with **no engine, no backend, no window** — neutral events in, a neutral `Visual` / `DrawListData` tree out. Layout, input, routing, focus, animation, and draw-list build are asserted directly on CPU. `Dump()` / `DumpLayout()` / `DumpState()` snapshot surfaces make every stage inspectable. The current suite is ~225 tests across ~44 files with no GPU reference; this invariant is a design driver, not a later phase.

## 3. Load-bearing pillars (protect these)

- **Core depends on StbImageSharp only.** HarfBuzz and the MSDF generator stay satellites. Adding a runtime dependency to `SUIsei` core is a design violation.
- **Headless by construction** (above) — no engine handle in any logic type.
- **`IUICompositor` is a public portability boundary** — keep the `Visual` / `ContainerVisual` / `SpriteVisual` / `RootVisual` + content (`Rect` / `GlyphRun` / `Shape`) + paint (`Color` / `LinearGradient` / `Surface` composition brushes) surface small and dumpable; a foreign engine must be able to consume it without ever producing `DrawListData`. Content is retained and versioned, as WinUI's composition objects are: an element updates its content object in place, and a compositor reads `VisualContent.Version` to see what changed and to key the work it derives from it.
- **The `SUIsei.Drawing` ↔ host layout contract is byte-identical** — the zero-copy cast depends on it; change neither side without the other.
- **NativeAOT-clean** — typed DP delegates, generated `new`/setters, no `Activator`/`MethodInfo`/`Type`-keyed maps anywhere in the property / binding / template / resource path.
- **No allocations on the hot path.** `UIHost.Tick`/`Render`, routed-event dispatch, hit-testing, and the compositor's draw-list build allocate no managed memory on a steady-state frame — pooled route chains + args, retained/cached vertex buffers, the dirty-flag no-op short-circuit — especially in Release. Allocation belongs to construction and layout/structure changes, not the per-frame path.
- **DP precedence ladder:** `Animation > Local > Style > Inherited > Default`, with the animation rung present from day one; coercion applies to the **resolved** value (per read), not per-rung. (Dense `GlobalIndex` slots assigned via `[ModuleInitializer]`.) The value store is typed and boxing-free: a property's rungs live in a slot of its own value type, made on its first write to an object, so writes, coercion, change checks, change callbacks and `{TemplateBinding}` pushes never box. An animation writes a property every frame, so this is what keeps animating frames allocation-free. A DP is animatable when it has a `Lerp` (declared in its metadata, or standard for float, double, `Vector2`, `Vector3`, `Point` and `HdrColor`); storyboards reach it through a compile-time `PropertyPath`, and `AnimationClock.Tween` drives it, or any CLR property, from code.
- **Group opacity is true render-to-texture (Strategy A):** the GPU-free compositor emits zero-geometry `BeginLayer`/`EndLayer` markers; the host backend renders the subtree into an offscreen target over the layer's rect and composites it at the group alpha. `SUIsei.Rasterizer` is the byte-identical CPU oracle for every drawable kind: it shades each with the GPU's math, applies the GPU's top-left fill rule (a pixel centre on an edge two triangles share is drawn once), clips a layer's content to its rect, and pools its layer framebuffers.
- **Independent animation:** transform/opacity/brush animations write the `Visual` directly and recomposite the dirty subtree **without re-running layout or the element walk**: a `Transform` change recomposes the element's visual transform, `UIElement.Translation` writes it, and a brush change recolours its shared composition paint in place and marks its users' visuals dirty.

## 4. The published XAML subset (a hard contract)

The generator errors clearly on anything outside this grammar; the subset is a published contract, not "best-effort WinUI." `XamlSubsetContractTests` holds it as a test: every **In** form must generate with no diagnostic and compile, and every **Planned** form must be reported.

**In:** elements/attributes; `x:Class` / `x:Name` / `x:Key` / `x:DataType`; property-element syntax for any settable property, collection or attached property (`<Border.Padding>4,8</Border.Padding>`, `<StackPanel.Children>`, `<Canvas.Left>`), holding text, one object, or a collection's items; content + attached properties; event handlers; markup extensions `{x:Bind}` / `{StaticResource}` / `{TemplateBinding}` / `{x:Null}` / `{x:Static}`; `<Style>` / `<Setter>` (+ `BasedOn`, `<Setter.Value>`, and attached-property setters such as `Property="Canvas.Left"`); `DataTemplate` / `ControlTemplate` / `ItemsPanelTemplate`; `ResourceDictionary` with inline `MergedDictionaries`; Grid row/column definitions; geometry, as elements (`PathGeometry` with `PathFigure`s of `LineSegment` / `PolyLineSegment` / `BezierSegment` / `PolyBezierSegment` / `QuadraticBezierSegment` / `PolyQuadraticBezierSegment` / `ArcSegment`, `RectangleGeometry`, `EllipseGeometry`, `LineGeometry`, `GeometryGroup`) or as WinUI path markup wherever a `Geometry` is taken, a geometry's `Transform` (`<RectangleGeometry.Transform>`), and `UIElement.Clip` (`<Border.Clip><RectangleGeometry Rect="0,0,50,20" /></Border.Clip>`); `mc:Ignorable` design-time markup (`d:`), which is skipped; `VisualStateManager` groups/states with `<Storyboard>`s of `DoubleAnimation` / `ColorAnimation` / `DoubleAnimationUsingKeyFrames` (`Linear` / `Discrete` / `EasingDoubleKeyFrame`) and `<X.EasingFunction>` elements (`CubicEase`, `QuadraticEase`, `BackEase`). `Storyboard.TargetProperty` takes WinUI property paths — `Opacity`, `(UIElement.Opacity)`, attached `(Canvas.Left)`, and `(Owner.Property).(Owner.Property)` steps through properties that hold objects, such as `(Border.Background).(SolidColorBrush.Color)`, `(Border.Background).(Brush.Opacity)` and `(UIElement.RenderTransform).(CompositeTransform.TranslateX)` — resolved to dependency properties at compile time; a step may name a more derived type than the property before it holds, and the object found is checked when the animation begins. The shorthand from before brushes and transforms (`TargetProperty="Background"` on a `ColorAnimation`, `RenderTransform.Translate.X`) is SUISEI023, whose message gives the WinUI path. Brushes (`SolidColorBrush`, `LinearGradientBrush` with `GradientStop`s, `ImageBrush`) and transforms (`TranslateTransform`, `ScaleTransform`, `RotateTransform`, `SkewTransform`, `CompositeTransform`, `MatrixTransform`, `TransformGroup`) are object elements like any other, set through property elements (`<Border.Background>`, `<Border.RenderTransform>`); `<X.BackgroundTransition><BrushTransition/>` too. A `ResourceDictionary` holds any keyed object, not only styles, so a brush resource is shared by every element that names it with `{StaticResource}`. `{x:Bind}` supports `OneTime` / `OneWay` / `TwoWay`, deep paths with INPC re-subscription, and `fallback` / `target-null`. `{StaticResource}` resolves while the tree is built, through the dictionaries of the element's markup ancestors (and their merged dictionaries), innermost first.

**XML namespaces.** The default namespace, `https://github.com/AtomicBlom/SUIsei/ui`, maps `SUIsei.Controls`, `SUIsei`, `SUIsei.Media`, `SUIsei.Shapes`, `SUIsei.Documents` and `SUIsei.Animation`, searched in that order, as WinUI's maps `Microsoft.UI.Xaml` and its sub-namespaces. `xmlns:local="using:My.Namespace"` maps one CLR namespace, for an app's own elements and for the owners `{x:Static}`, `x:DataType`, `TargetType` and property paths name. Any other namespace is foreign: its elements are unknown (SUISEI003) and its attributes are ignored with a warning (SUISEI013), unless `mc:Ignorable` lists its prefix.

**Values.** Text converts at compile time through one converter table keyed by the target type, shared by every value position: attributes, `<Setter Value>` and `<Setter.Value>`, attached properties, property-element text, animation `From` / `To` / `By` / `Duration` / `KeyTime` / `Value`, easing parameters, and `{x:Bind}`'s `FallbackValue` / `TargetNullValue`. It covers `HdrColor` (`#RRGGBB`, `#AARRGGBB` or a WinUI named colour such as `CornflowerBlue`), `Brush` from the same colour text (a new `SolidColorBrush`, as WinUI's brush converter makes), `Thickness` (one, two or four numbers), `CornerRadius` (one or four), a `MatrixTransform`'s `Matrix3x2` (six: `M11,M12,M21,M22,OffsetX,OffsetY`), `Point` and `Vector2` (two numbers), `Size` (two, of 0 or more), `Vector3` (three), `Rect` (`x,y,width,height`), `PointCollection` (pairs, `0,0 10,5 20,0`), `DoubleCollection` (numbers), `Geometry` (WinUI path markup: an optional `F0`/`F1` fill rule, then figures of `M`, `L`, `H`, `V`, `C`, `S`, `Q`, `T`, `A` and `Z` commands, lowercase relative), `GridLength` (`Auto`, `*`, `N*` or pixels), `TimeSpan`, `RepeatBehavior`, enums, numbers, bool and string; numbers are separated by commas or whitespace and must be finite. A value its type cannot hold is SUISEI012 at its XAML line, and path markup that breaks its grammar is SUISEI024, naming the character where it went wrong. The colour, number and path-markup syntax are source files compiled into both the runtime (`HdrColor.Parse`, `Geometry.Parse`) and the generator, so both accept the same text; path markup is checked at compile time and parsed when the view is built.

**Extensions (`suisei:` xmlns).** `xmlns:suisei="https://github.com/AtomicBlom/SUIsei/extensions"` maps `SUIsei.Extensions`: SUIsei-only types and attached properties with no WinUI counterpart, kept out of the default namespace so that WinUI markup stays WinUI and SUIsei's additions are visible as such. Its members are used like any other: `<suisei:Type>`, `suisei:Owner.Prop="…"`, `<suisei:Owner.Prop>`, `<Setter Property="suisei:Owner.Prop">` and the property path `(suisei:Owner.Prop)`. A name that does not resolve in it is SUISEI022. The rule covers SUIsei's own controls too: a public element member that WinUI does not have is an attached property here, not a member. Those today are `suisei:Clipping.ClipToBounds` (WinUI clips with `UIElement.Clip`, a geometry), `suisei:Scrolling.WheelScrollAmount` on a `ScrollViewer`, and `suisei:Virtualization.RowHeight` on a `VirtualizingStackPanel` (set on the panel inside an `ItemsPanelTemplate`, whose attributes are honoured like any template root's).

**Planned** (in the contract but not implemented; each is reported, never ignored): `{ThemeResource}` (SUISEI007 until the theme system exists); `ResourceDictionary Source="…"`, a dictionary loaded from another file (SUISEI020).

**Out (v1):** `{Binding}` (reflection-based); **`{x:Bind}` function paths and value converters** *(these were in the original plan but are deliberately excluded from the supported subset — they diagnose)*; `x:Phase`; `x:DeferLoadStrategy`; conditional XAML; custom markup extensions; `x:Uid` / localization markup; `RelativeSource`; implicit data templates by type.

Generated output is locked down by snapshot tests over representative `.xaml`; diagnostics carry the XAML `file:line` (24 distinct diagnostic codes today), and every malformed form is an error rather than a warning, except foreign or ignored content (SUISEI013) and a TwoWay binding downgraded to OneWay (SUISEI014). Incrementality keys on a `CompilationSnapshot` whose equality compares only the XAML input + a fingerprint of the type surface (each public or internal type of the current assembly and each public SUIsei type, with its members' accessibility, types, parameters and accessors), computed once per compilation, so body-only C# edits re-emit nothing while a changed member type regenerates; XAML Hot Reload is supported.

## 5. Current capabilities (the baseline)

Shipped and headlessly verified: the full DP / precedence / coercion / template-binding store; the element tree + two-pass measure/arrange (Grid pixel/auto/star + span, StackPanel, Canvas, Border, ContentPresenter/ItemsPresenter) with invalidation + frame-level no-op; a broad control set (TextBlock, Button, ToggleButton, CheckBox, Slider, ScrollViewer, TextBox, Popup, MenuFlyout(Item), MenuBar, ListView/ListViewItem, ItemsControl, Image); the composition tree + `DrawListCompositor` with damage tracking, incremental recomposition, and group-opacity layers; routed events (tunnel/bubble/direct, `Handled`, pooled chains, synthesized `Click`), hit-testing through the composition (below), focus + Tab (one tab order across views; `TabFocusNavigation` is not read), pointer capture/drag; `Control.IsEnabled` with WinUI's semantics (below); storyboard/keyframe/easing animation + `AnimationClock` + `VisualStateManager`; ItemsControl/ListView with `INotifyCollectionChanged` + `VirtualizingStackPanel`; the source generator (x:Bind OneTime/OneWay/TwoWay/fallback/deep paths/INPC, events, ControlTemplate/DataTemplate + item-scoped binds, TemplateBinding, Style/Setter/BasedOn, StaticResource/ResourceDictionary/merged, storyboard + VSM codegen); an MTSDF `FontAtlas` (codepoint + glyph-id) with the `ITextShaper` seam, a default advance-based shaper, a HarfBuzz satellite shaper, and a **native managed MTSDF generator + atlas baker + OpenType reader**; the HDR paper-white colour path; the `SUIsei.Rasterizer` CPU oracle; and the `SUIsei.Gallery` demo.

**Enabled state.** `IsEnabled` belongs to `Control`, as in WinUI; plain elements (Border, Panel, TextBlock, Image…) have none and leave input with `IsHitTestVisible`. It is inherited: while a control is disabled every control beneath it reads `IsEnabled == false` (a value set on it is kept for when the ancestor is enabled again), and `IsEnabledChanged` fires on each control whose effective value moves, including when one is attached under or detached from a disabled control. A disabled control takes no focus (Tab skips it, `TrySetFocus` refuses it, and the host releases focus from one disabled while focused before it routes the next keys), handles no pointer or keyboard input on itself, and shows its `CommonStates` `Disabled` state, or `Normal` where its template has no `Disabled`. Hit-testing follows WinUI's documented rule that a disabled control is "still visible to hit testing": it blocks pointer input to whatever lies behind it, and the input it sources still bubbles to its ancestors, which may handle it.

**Brushes and transforms.** `Background`, `BorderBrush` and `Foreground` are `Brush` dependency properties, on the owners WinUI gives them (`Border`, `Panel`, `ContentPresenter`, `TextBlock`, and `Control` with its `BorderThickness`); `Border.CornerRadius` is WinUI's `CornerRadius`, drawn uniform only, so radii that differ throw `NotSupportedException` when set. `RenderTransform` is a `Transform` applied about `RenderTransformOrigin`, and WinUI 3's `UIElement.Translation` is a plain `Vector3` property that writes the visual's transform directly, after the render transform, with no layout; `Translation.Z` is kept but moves nothing in 2D, as in WinUI without a perspective. Hit-testing and `TransformToVisual` follow both; `AnimationClock.Tween` animates `Translation`.
- **Sharing.** A brush or transform may be shown by many elements (a `ResourceDictionary` brush, a style's setter value). An element registers with the brushes and transform it shows while it is in a live tree and unregisters when it leaves, so a long-lived brush keeps no removed element alive, including the trees a hot-reload rebuild replaces. A change updates the brush's composition paint in place and marks its users' visuals dirty, with no layout and no allocation; gradient stops and transform-group children forward their changes the same way. A storyboard on a shared brush animates every user, as in WinUI; an element that should animate alone needs a brush of its own.
- **Unset means the built-in look.** A null `TextBlock.Foreground` paints white, and a control's null `Background` / `BorderBrush` / `Foreground` shows its template's own look; WinUI would read back its theme brush there. The built-in look's brushes are sealed: shared by every control, on every thread, they keep no listeners and throw if anything writes to them.
- **Built-in templates** paint the control's `Background`, `BorderBrush`, `BorderThickness` and `Foreground` where WinUI's default templates do (Button, ToggleButton, MenuFlyoutItem, MenuBarItem; CheckBox's row and label; Slider's rail and fill; TextBox's chrome; ListViewItem's own background). As in WinUI, the pointer-over and pressed states show the template's own brushes rather than tinting `Background`, and the resting state hands the control's back; `BrushTransition` (WinUI's, on `Border` / `Panel` / `ContentPresenter`) fades between solid colours, and as an extension also fades a colour in or out to or from no brush. `Foreground` reaches the text a control or presenter makes for string content; it is not yet inherited by text inside element content.

**Hit-testing.** A pointer hits what is drawn under it. The walk follows the composition the compositor draws: each element's visual transform is composed down from the root's DIP→pixel scale, so render transforms, `Translation`, scroll offsets and `LayoutScale` all count, and overlays are tested above content. Clips are intersected as the compositor applies them, as surface-space bounding boxes; under rotation that box is larger than the rotated clip, and a point in its corners hits whatever is drawn there, so the pointer agrees with the pixels rather than with the ideal clip shape. An element is a hit only where its content draws, one case per content kind: a rect over its bounds, except that a rect filled only by an image covers just the image (not the letterbox), and text over its layout bounds. `IsHitTestVisible = false` removes an element and its subtree. `UIElement.TransformToVisual` and `PointerRoutedEventArgs.GetCurrentPoint` map points through the same composed transforms, so controls never sum layout offsets themselves. Hit-testing and routing a pointer move allocate nothing.

**Geometry.** `SUIsei.Media` has WinUI's geometry model: `PathGeometry` (figures of line, poly-line, Bézier, poly-Bézier, quadratic, poly-quadratic and arc segments), `RectangleGeometry`, `EllipseGeometry`, `LineGeometry` and `GeometryGroup`, with `FillRule`, `PointCollection` and `DoubleCollection`. Every property is a dependency property. A change anywhere in a geometry, down to one point, reaches its owners synchronously: the figure or group holding it, and each element using it while that element is in a live tree (as with brushes and transforms, it registers when it joins a live tree and unregisters when it leaves, so a geometry in a resource dictionary keeps no removed element alive). Each geometry keeps a `CompositionPath`, the neutral, versioned path the compositor and the tessellator read (arcs as cubic Béziers of at most 45°), rebuilt in place after a change; `PointCollection.SetAll` (SUIsei-only, code-only) replaces a poly segment's points with one change and no allocation. Figures and segments belong to one collection at a time, as in WinUI. `Geometry.Transform` maps a geometry's points where it is used (a group's children, a clip, a tessellation), never its path, so moving it rebuilds nothing; a stroke follows the mapped outline at its own thickness, and `Bounds` are the tight bounds of the mapped curves. The tessellation cache is keyed by the path (object and version), the path transform, the stroke style and the scale bucket. `UIElement.Clip` (a `RectangleGeometry` in the element's own coordinates, through its `Transform`) clips the element's subtree and its hit-testing; with `suisei:Clipping.ClipToBounds` as well, the element clips to the intersection; a change to the clip rectangle or its transform applies at the next composite with no relayout, so a storyboard on `(UIElement.Clip).(Geometry.Transform).(TranslateTransform.X)` slides it. Clips are axis-aligned rectangles, so a rotated or skewed clip transform clips to the bounds of the turned rectangle, as a rotated element's clip already does.

**Tessellation.** `SUIsei.Drawing.Tessellator` is public and dependency-free, so a foreign compositor can use it too. It turns a `CompositionPath` into triangles, three vertices each and never shared, in a retained `TessellatedPath`; re-tessellating a path of a steady size allocates nothing.
- **Antialiasing data:** every vertex carries up to four signed distances (positive inside, in the path's units, linear across its triangle) to the edges its triangle antialiases, with unused slots at a large constant that reads as inside. A renderer turns each into pixels by dividing by its screen-space gradient, so edges are exact at any position, rotation or scale.
- **Scale buckets:** curves are flattened to within a quarter pixel at the top of a half-octave bucket of the largest scale the transform applies (`TessellationScale`), and antialiasing margins are half a pixel at the bottom of the smallest scale's bucket, so they never get narrower than a pixel.
- **Strokes** (`CompositionStrokeStyle`, with WinUI's defaults and semantics): miter (cut off at the miter limit, in half thicknesses), bevel and round joins; flat, square, round and triangle caps; dashes in thicknesses, restarting at each figure, with the dash cap where a dash does not end at a figure's start or end, and a closed figure's dash crossing its start drawn as one dash through the closing join. A figure with no length draws its caps back to back as a dot. A body carries its two sides and any cap clip; joins and caps are split on their bisectors so each triangle antialiases one outer edge, and round ones are fans of tangent lines. Every vertex carries its arc length along the whole geometry.
- **Trim** (`PathTrim`, WinUI's `CompositionGeometry.Trim*` over the whole geometry's length, wrapping with the offset) applies at emit (`TessellatedPath.Emit`): pieces inside the trim are drawn from the cache, the segments it cuts are rebuilt to the cut with the start or end cap there, and a closed figure trimmed across its start runs through its closing join. A trimmed stroke draws exactly what stroking the trimmed part of the path would, and animating a trim never re-tessellates or allocates. Fills are not trimmed.
- **Drawing it:** `DrawListBuilder` (public) appends a `TessellatedPath` to a draw list as the `Vector` prim, transformed, coloured, trimmed and optionally textured, splitting across index windows at triangle boundaries, and building lists of a steady size allocates nothing. It is the way from tessellated paths to vertices and commands for a foreign compositor, a host's own overlays and tests. With a group opacity below 1 the path draws inside a layer of its own whose tint carries that opacity: drawn opaque in it, a translucent stroke's joins and self-crossings blend once and match the rest of it. A stroke whose alpha varies along it (a gradient's alpha) still blends twice where it overlaps itself inside its layer; that is a gap.
- **Fills** under the path's fill rule (even-odd or nonzero): figures may nest (holes, islands), cross themselves and cross each other. Figures that neither cross nor touch are ear-clipped (after mapbox's earcut, ISC). Any others go through a sweep-line tessellator, a port of libtess2's (Eric Veach's GLU tessellator, SGI Free Software License B; `THIRD-PARTY-NOTICES.md`), which resolves the crossings into the filled region's boundary; that boundary is inset and triangulated in turn under the positive winding rule. The interior is inset by half a pixel and every edge of the filled region (never an edge inside it) gets a one-pixel fringe straddling it, carrying that edge's distance, so the coverage ramp sits on the edge and a translucent fill blends once everywhere. This is near-exact: at a reflex corner each fringe takes its own edge's ramp, so the notch is a little light where two ramps would combine, features under a pixel wide can fold the inset over, and corners sharper than about 30° have their fringe cut short.

**Shape content.** `ShapeContent` is the composition content of a vector shape, as WinUI's `CompositionSpriteShape` is: a `CompositionPath` drawn through a `PathTransform` (a geometry's transform, a shape's stretch; it maps the outline, not the pen), fill and stroke `CompositionBrush`es measured over the path's tight `Bounds`, a retained `CompositionStrokeStyle` and a `PathTrim`. It is retained, versioned (its path, style and brushes version themselves, as a rect's brushes do) and dumpable. Its fill and stroke tessellations are cached on it, keyed by the path (object and version), the path transform, the style's version and the scale bucket, so moving, fading, recolouring or trimming a shape never re-tessellates it. A foreign compositor draws the path natively, or takes the same triangles from `TessellateFill` / `TessellateStroke`.
- **Drawing it:** the compositor emits the `Vector` prim. A colour paints per vertex. A linear gradient is exact: each triangle is cut where the colour stops being linear, and the pieces keep its edge distances, so they antialias as it would; a crossing is computed from its edge's lower corner, so neighbouring triangles cut a shared edge at the same points. An image samples the prim's texture slot, placed in the bounds by the brush's stretch and alignment; where it does not cover them (a letterboxed `Uniform`), the shape is clipped to the image's rect, or under a rotation to that rect's bounds on the surface.
- **Translucency:** a stroke that can overlap itself (more than one segment) painted with one alpha below 1 (a colour, or a gradient whose stops share it) draws opaque inside a layer that carries the alpha, so its joins and crossings blend once. A faded shape with both a fill and a stroke draws into one layer the fade applies to, so the fill does not show through the stroke's inner half. Paint whose alpha varies (a gradient whose stops differ in alpha, an image) still blends twice where a stroke overlaps itself; that is a gap.

In-world surfaces, camera-ray hit-testing, and billboards are implemented in the **host glue** (`Loom.UI.SUIsei`), so SUIsei itself stays purely 2D and neutral (`UIHost.Tick` takes no camera; `CreateRoot` takes a 2D layer).

## 6. Remaining work

- **Rich text layout** — a `TextLayoutEngine` that itemizes (script/direction/font), shapes, line-breaks (UAX-14), and wraps; rich inline runs; a `FontFallbackChain` + `.notdef`/tofu glyph; build-time missing-glyph warnings. `TextBlock` is single-line advance-based today.
- **Cross-platform HarfBuzz** — the `ITextShaper` seam is wired (`FontAtlas` measure and run-build go through it) and the Gallery installs `HarfBuzzTextShaper`; what remains is shipping HarfBuzz native assets for Linux/macOS (Win32-only today). Platform shapers (a Windows `DWriteTextShaper`, a macOS Core Text one) are a clean drop-in at the same seam — capability-gated like a backend, not the default — and are deferred by decision; a full DWrite *bitmap* engine replacing MTSDF is explicitly rejected, as it would abandon resolution-independent, cross-platform-parity, AOT-clean text.
- **Native MSDF generation as the bake path** — `SUIsei.Text` / `SUIsei.Text.Tool` exist and replace the external `msdf-atlas-gen`, but are **not wired into the build**: add a `RegisterFonts` MSBuild target so fonts bake from a fontset at build time (the default atlas is currently a static embedded blob). Deferred within the generator: GPU-compute rasterization (the `IMsdfRasterizer` seam is ready for it), font hinting, variable-font axes, subset-`.ttf` emission for the shaper, and weight/script-aware font selection.
- **Gamepad + XYFocus spatial navigation** — the input enums exist; the directional scoring heuristic (with tunable weights + a debug overlay) is unimplemented, and there is no `GamepadInput` queue yet.
- **IME** — committed-character text input works; add an `ITextInputProvider` host seam so per-OS IME lands without reworking `TextBox`.
- **NativeAOT CI gate** — the libraries set `IsAotCompatible`, but there is no `PublishAot` smoke-publish (warnings-as-errors) gate in CI.
- **Deferred:** multi-screen hosts, in-world occlusion (the analytic ray test ignores scene depth; opt-in depth-sampled occlusion is a later escape hatch), above-paper-white roll-off (hard clamp vs soft knee), and compositor threading.

## 7. Open risks

- **Rich-text / shaping is the biggest remaining greenfield** — mitigated by prebake + fallback + tofu + build-time warnings, with HarfBuzz as the proven shaper behind the swappable seam.
- **The XAML subset must stay a published hard contract** — and the contract must be reconciled with what shipped (function paths and converters were dropped from the supported `{x:Bind}` subset; §4 reflects the real state, and `XamlSubsetContractTests` fails when the two drift apart).
- **Composition-tree sync** — the element tree must push layout/property deltas into the visual tree and keep damage flags honest, or incremental recomposition drifts. Mitigated by making both trees dumpable and asserting *element → visual → draw-data* as separate pure stages.
- **The `SUIsei.Drawing` ↔ host byte-identical layout contract is load-bearing and unguarded** — a layout drift on either side silently corrupts the zero-copy cast; an analyzer or a layout-assertion test would harden it.
- **XYFocus heuristic** needs tuning (WinUI's constants are private) — ship tunable weights + a debug overlay.

## 8. Verification

The strategy is **graphics-framework-free by design** — almost the whole runtime is exercised by fast, deterministic CPU tests; only the host backend's *pixels* need a GPU:

- **Unit tests** (`SUIsei.Tests`, TUnit + Shouldly, no backend reference): DP precedence (incl. the animation rung); Grid star/auto/measure-arrange; the neutral draw-list seam (assert the `DrawListData` vertex/command stream); 2D + ray→UV hit-testing; routed-event tunnel/bubble ordering + `Handled`; storyboard interpolation; the `SUIsei.Rasterizer` group-opacity oracle; text against a committed font fixture.
- **Source-generator snapshot tests** over representative `.xaml`, with diagnostics carrying the XAML `file:line`.
- **Host-side pixels only** — the integrating engine captures a deterministic frame and pixel-diffs across its backends (in Loom: Vulkan vs DirectX 12). Everything above the final draw-list submit is covered by the CPU tests.
