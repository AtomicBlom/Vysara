**Date:** 2026-10-28. The review ran in two passes.
- **First pass:** `c7c4e65..6a9184d`, findings R-01 to R-24. Their `path:line` references are as of `6a9184d`.
- **Second pass:** PRs #74 to #80, which merged while the first pass ran (`6a9184d..de43d72`). It reports the status of every earlier finding on `de43d72` (the table after the verdict) and adds findings R-25 to R-37, whose references are as of `de43d72`.

**Question asked:** do these changes honour the locked decisions, the load-bearing pillars and the guidelines in `Planning.md` §1–4, and do they make sense?

## Verdict

**The expensive pillars held.** These would be costly to win back, and the new code keeps them:
- **Dependency floor:** core still depends on StbImageSharp alone. The tessellators are in-core and dependency-free, and the libtess2 and earcut notices ship in the package.
- **NativeAOT:** ILC is clean over the core and over generated code.
- **Draw contract:** the `OverlayVertex` / `DrawCommand` byte layouts are untouched. `Vector`, per-slot alpha and colour space, and text effects all came in through `Custom` and the slot table, as §2 describes.
- **No hot-path allocation:** about 25 allocation tests back it, across recomposite, storyboards and tweens, hit-testing, shaping, tessellation, trim and bitmap rewrites. Each measures windows of many frames, so an allocation made every frame still fails.
- **WinUI fidelity of the new object model:** names, defaults and enum members are WinUI's wherever they were checked. That includes stroke defaults, `Stretch` per type, gradient endpoints, transform order, and skew and rotation signs.

**The drift is in four themes, not in the architecture:**

1. **Fail-loud has become fail-late.** Several values are accepted where they enter and then throw later from the per-frame path (`Render`, layout, the animation clock, the tessellator). The result is not a clear error. It is a frozen surface, a wedged layout pass, a stale tessellation, or a popup that swallows every click. This is the theme that hurts the game most directly. (R-01 to R-07)
2. **Lifetime is wired by hand.** Live-tree registration is one good primitive wired in about 30 places under three different lifetime rules, and one step is already missed. When a subtree leaves or is rebuilt, focus, capture and running storyboards are not released. A visual-state storyboard that has finished can't be released by leaving its state. (R-08 to R-11)
3. **The §4 "hard contract" is softer than it reads.** The generator silently drops WinUI markup: the Out-list `x:` directives, `<VisualState x:Name>` and `VisualState.Setters`. It also reads `TimeSpan` differently from WinUI. The contract test has no Out table, so it can't notice. Most of this predates `c7c4e65`, but this range rewrote §4 and added the contract test without closing it, and the test encodes the non-WinUI `Name=` form. (R-12 to R-15)
4. **The portability boundary got bigger and leakier.** About 15 new public composition types live in the root `SUIsei` namespace, which the default XAML namespace maps, and they take `SUIsei.Media` enums (the brushes went the other way). `Visual` has no version, a foreign compositor's output can't reach the host, and `DrawListBuilder` is public but partial. This is cheap to fix now, and becomes a breaking change once Loom or another engine binds to it. (R-16 to R-18)

**PRs #74 to #80 fixed some of this and added a fifth theme.**

What they fixed, each confirmed against `de43d72`:
- **Visual states now work as WinUI's do in the common case.** An empty resting state releases a finished state's values (#78, R-08). `<VisualState x:Name>` is read (R-13).
- **A style can re-template a built-in control** (BuiltInStyle, R-20).
- **The Inherited rung is finally used** (#77, R-21).
- **`ControlTemplate` works in `<Setter.Value>` and as a keyed resource** (R-15).
- **Panel layout is allocation-free and tested** (#79).

The precedence ladder they introduce, `Animation > Local > Template > Style > BuiltInStyle > Inherited > Default`, matches WPF's and WinUI's documented order.

None of the fail-late findings (R-01 to R-07) was touched, and each that has a repro still reproduces.

5. **Diagnostics came into the core, and its guard doesn't hold.** #74 compiles a named-pipe endpoint that loads and runs code into `SUIsei.dll`. It comes from a submodule, behind one feature switch.
   - The switch is documented as always off under NativeAOT. It isn't: a game that opts in the documented way gets the loader compiled into its NativeAOT build, and a load request then kills the process (R-25, High).
   - The endpoint is a dependency in all but name (R-26), the switch opts into code loading as well as the in-process API (R-27), and its work queue is process-wide where hosts are per-window (R-28).
   - The in-process `Diagnostics` API itself is well built: off by default, no per-frame cost when off, and the tap a proper satellite. The endpoint is what belongs in a satellite.

The new PRs also extend the earlier themes:
- **Lifetime:** a replaced template stays wired (R-29), and a state change that throws leaves the manager half-updated (R-30).
- **The contract:** values set directly in a template still land on Local (R-31), and the new value forms drifted from §4 (R-35).
- **WinUI fidelity of inherited text:** built-in controls inherit a page's font size, which WinUI's default styles prevent (R-32).
- **Cost of inherited text:** a size animation re-shapes all the text below it (R-33), and line breaking is internal to SUIsei's own compositor (R-34).

### Theme 1 — Fail-late and robustness on the per-frame path

#### R-01 · `AnimationClock.Tween` on a validated property throws mid-animation · High · New · Repro
- **Principle:** §5 and `PropertyMetadata.Validate`'s own doc say an animation's values are checked as it begins, so "a running animation never throws". Also the precedence ladder: Animation > Local.
- **Evidence:**
  - The DP overload of `Tween` writes the **Local** rung every frame: `SUIsei/Animation/AnimationClock.cs:285` (`_target!.SetValue(_property!, …)`).
  - `SetRung` validates every write that isn't on the Animation rung: `SUIsei/DependencyObject.cs:104`.
- **Repro:** set `suisei:TextEffects.OutlineThickness` to 0.05, then tween it to 0 with WinUI's default `BackEase` (EaseOut overshoots). The clock throws `ArgumentOutOfRangeException` ("Actual value was -0.0006…") from inside `Advance`, i.e. from `UIHost.Tick` in a host.
- **Related, traced by a reviewer:**
  - `CaptureStart` validates `ValueAt(0)` (`AnimationTimeline.cs:110-114`). With no `From`, that is the value on screen, so taking over from an animation mid-overshoot throws in `Begin`, typically inside a pointer handler via `GoToState`.
  - Writing Local means a tween permanently replaces the author's local value and outranks a style.
- **Recommendation:**
  - Have DP tweens write the Animation rung, as storyboards do, and check only the start and end values when the tween starts.
  - Don't validate a start value that was read from the screen.
  - Add the test. Nothing covers `Tween` against `Validate` today.

#### R-02 · Paint the setters accept throws inside `Render`, and the surface then silently freezes · High · New · Repro
- **Principle:** fail loud where a value enters (§5's own rule for text effects), and the headless pillar's "`Render` runs to completion".
- **Evidence:** three things throw at draw time rather than where the value is set:
  - an sRGB gradient with a stop above 1 (`DrawListCompositor.cs:214`, `:272`, `:350`, `ThrowIfUndefined`); an overshooting colour easing can also produce one, since `Lerps.Color` doesn't clamp;
  - an image brush as a `TextBlock.Foreground` (`DrawListCompositor.cs:218`);
  - more than 65,536 gradient bands (`GradientSplitter.cs:99`).
- **`UIHost.Render` is not exception-safe** (`UIHost.cs:154-162`). By the time it throws:
  - `DrawLists` has already been cleared, and the views after the failing one are not drawn;
  - `TextureResidency.EndRender` doesn't run;
  - the compositor has already cleared `IsDirty` on the visuals it walked.
- **Repro:** set a gradient stop to `(2,2,2)` on a `Border`'s sRGB `LinearGradientBrush`.
  - The setter accepts it.
  - The next frame throws `InvalidOperationException`.
  - The next two frames don't throw. They re-submit the last good list (same `Revision`), so the change is silently lost.
  - The next unrelated change on that surface throws again.
- **Recommendation:**
  - Check at entry: a stop's colour against its brush's interpolation mode, and the kind of a text foreground's brush, as `TextEffects.ValidateBrush` already does.
  - In the compositor, degrade (clamp, skip) rather than throw.
  - Put `EndRender` in a `finally`, and re-dirty what a failed composite walked.

#### R-03 · A dash pattern that becomes too fine throws out of `Render`, and the half-built tessellation is then treated as current · Medium · New · Traced
- **Evidence:**
  - `Tessellator.Stroke.cs:354-356` throws past `MaxDashes`.
  - `Stretch` scales the outline, so a layout change can make a working pattern too fine, and the throw then happens during `Render`.
  - `TessellatedPath.Begin` records the cache key (`_sourcePath`, `_sourceStyle`, `_source`, `:104-106`) before any work, but `Version` only moves in `Finish` (`:127`).
- **Why it matters:** after the throw, `IsCurrentFor` (`:84-86`) answers true for a shape that had tessellated before. It then silently draws the partial dash set with the old `Length`, `SegmentCount` and `Bounds`, so trim fractions and hit-test bounds are wrong.
- **Coverage:** Planning doesn't mention the limit, and `A_dash_pattern_finer_than_the_limit_throws` covers only the first throw.
- **Recommendation:**
  - Record the key in `Finish`, or invalidate it in `Begin`.
  - Past `MaxDashes`, degrade (draw the rest solid) with a diagnostic instead of throwing mid-render.
  - Document the limit.

#### R-04 · The dash walk can draw stray joins and has no progress bound · Medium · New · Traced (reviewer emulated it)
- **Evidence:** `Tessellator.Stroke.cs:185-209` walks a dash along its segments with `while (r < r1 - 1e-6f)`. That ends a run by comparing a running float sum against a length summed separately, using an absolute epsilon, which is below one ulp once `r` passes about 8. It moves on with `next = index == last ? figure.FirstSegment : index + 1`.
- **What happens when the sums drift by an ulp:**
  - The walk adds a sliver body and a join at the far end of a segment the dash never reaches.
  - On an open figure's last segment, it wraps and draws a join at the figure's start.
  - If `r` stops advancing (segments shorter than half an ulp of `r`), it cycles round the figure, appending geometry until it runs out of memory, on the render thread.
- **Evidence from emulation:** the reviewer emulated the walk in float32 over 3,000 random polylines (319,315 dashes). It found 79 joins more than 0.05 units past a dash's end, and 20 wraps to an open figure's start.
- **Why the tests miss it:** they use integer coordinates on paths of 30 units or less, where float sums are exact.
- **Recommendation:**
  - Locate the end segment once, walk by index to it, and wrap only when the figure is closed.
  - Cap iterations at `SegmentCount + 1`.
  - Make the epsilons here and in `TessellatedPath` relative to the length.
  - Add a regression test: dashed polylines with non-integer coordinates.

#### R-05 · A non-uniform `CornerRadius` is stored before it throws, wedging every later layout · Medium · New · Repro
- **Principle:** the published contract (§5: radii that differ "throw `NotSupportedException` when set"), and fail loud.
- **Evidence:** `Border.cs:37` throws from `PropertyChanged` (`_ = value.Uniform; // fail loud now`). That runs after the value is stored (`DependencyObject.cs:104-122`: `Validate` runs before the store, `PropertyChanged` after it).
- **Repro:** after the rejected set, `border.CornerRadius` reads `(1,2,3,4)`, and every later `LayoutPass` on that root throws.
- **Wider effect:**
  - The generator accepts `CornerRadius="1,2,3,4"` (`XamlSourceGenerator.Values.cs:152`), so the error only shows at runtime.
  - A style setter takes the same path and throws part-way through applying.
- **Recommendation:** move the check into `PropertyMetadata.Validate`, which this range added for exactly this, and report a literal non-uniform value as SUISEI012.

#### R-06 · The text-effect font-range check depends on order, uses a different limit from the renderer, and throws from surprising places · Medium · New · Traced + Reviewer
- **Principle:** coherence of "validate where a value enters"; core `UIRoot` coupled to one extension.
- **Order dependence:** `Validate` reads tree state (`TextEffects.cs:49`, `text.AttachedRoot?.Font`), so the same value can throw or be silently clamped:
  - it is checked when the text becomes a root's `Content`;
  - it is not checked when the text is adopted into a live panel or template;
  - it throws when set later, on text already in the tree.
- **Coupling:** `UIRoot` hard-codes `Extensions.TextEffects.ValidateTree` at three sites (`UIRoot.cs:41`, `:83-85`, `:97`).
- **Limit mismatch:** the check allows `DistanceRangeEm / 2` (0.1875 EM). The emitter clamps the bias to `0.5 − 0.5/screenPxRange` (`UIDrawList.cs:257`), which is 0.152 EM at 14 px. So the largest "valid" outline is never drawn as set, at any finite size.
- **Surprising throw sites:**
  - `Popup.IsOpen`;
  - a visual-state begin during input routing;
  - an `{x:Bind}` push inside a view model's `PropertyChanged`;
  - `Style.Apply`, part-way through its setters.
- **Popup, traced:**
  - `Popup.cs:63` adds a full-surface, hit-visible dismiss layer.
  - `:65` then throws in the check, so `_shown` stays false.
  - `Hide()` therefore returns early, and the dismiss layer stays: every press on the surface is swallowed.
- **Recommendation:**
  - Keep `Validate` value-only: negative, non-finite, image brush.
  - Replace the font-range throw with the clamp the emitter already applies at draw time, plus a diagnostic (a flag in `Visual.Dump()`).
  - Drop the `ValidateTree` hooks from `UIRoot`.

#### R-07 · The antialiasing margin comes from the smallest stretch and applies in every direction · Medium · New · Traced (visual effect suspected)
- **Evidence:**
  - `TessellationScale.HalfPixel` comes from `MarginBucket`, the transform's smallest stretch (`TessellationScale.cs:36`).
  - A singular transform falls to `MinBucket` (`:45-52`), which gives a half-pixel of 32,768 units.
  - Fill insets and fringes (`Tessellator.Fill.cs:126,156,178-181`) and stroke bodies (`StrokePrimitives.cs:52`) use that margin in every direction.
- **What happens:**
  - At `ScaleY = 0.1` the margin is about 5.7 px along X. Features narrower than about 11 px fold their inset, and on the ear-clipped path a translucent fill would cover those pixels more than once, showing darker stripes.
  - At `ScaleY = 0`, the start of the usual expand animation, fringes and stroke bodies reach ±32,768 units, which inflates layer bounds and overdraw.
- **Docs:** §5 says only that "features under a pixel wide can fold".
- **Recommendation:**
  - Cap the margin at a few flatten-bucket half-pixels, and accept a narrower ramp along the squashed axis.
  - Skip tessellation when the smallest stretch is near 0, since nothing is visible.
  - Document the behaviour.

### Theme 2 — Lifetime, wired by hand

#### R-08 · A finished visual-state storyboard can't be released by leaving its state, and handovers flash · High · Older (made common by this range) · Traced · **Mostly fixed in #78** (see the status table)
- **Principle:** the §4 `VisualStateManager` contract and WinUI's semantics.
- **Evidence:**
  - `AnimationClock.Advance` drops a storyboard once every child has completed, leaving `HoldEnd` values applied (`AnimationClock.cs:122-123`).
  - `Stop` releases only storyboards that are still active (`:63-72`).
  - So WinUI's standard empty resting state, `<VisualState x:Name="Normal"/>`, releases nothing once the pointer-over animation has finished. The colour stays.
- **Why this range makes it common:** the built-in templates moved to brush animations, and WinUI brush paths were published (`(Border.Background).(SolidColorBrush.Color)`). Every user template now hits this.
- **The built-ins work around it.**
  - `Controls/TemplateStates.cs:11-14` says "leaving the state that holds a brush cannot release it", and each resting state carries a `RestoreBackground` storyboard instead.
  - `DiscreteValueAnimation.cs:4-6` claims the opposite: "leaving the state releases it".
- **Handover flash (reviewer):**
  - `UIHost.Tick` advances the clock before draining pointers (`UIHost.cs:132-145`).
  - `GoToState` then calls `Begin(next)`, which writes nothing yet, and `Stop(previous)`, which releases the shared property.
  - So the frame rendered in between shows the base value.
- **Recommendation:**
  - Keep finished `HoldEnd` storyboards on a filling list that `Stop` can release, then delete `RestoreBackground`.
  - Apply the first frame on `Begin`.
  - Don't release properties that `next` animates.
  - Add a test with an empty `Normal` state.

#### R-09 · A storyboard's target path is resolved only once, so it keeps animating a replaced brush · Medium · Older mechanism, new consequence · Traced
- **Evidence:**
  - `AnimationTimeline.cs:86` returns early once `Apply` is set, so later `Begin`s never walk the path again.
  - `PropertyPath.cs:6-8` says the steps are walked when the animation begins.
- **Why it matters now:** before this range a target was a property on an element, so caching was harmless. Now a path walks through objects (7ce43ea). If `Border.Background` is replaced (by a TemplateBinding, an `{x:Bind}` or a style), the state storyboard keeps animating the old brush, which may be a shared resource and recolour other elements.
- **Recommendation:** re-resolve on each `Begin`, caching the bound delegates per owner and property so it stays allocation-free.

#### R-10 · An element re-added to a live tree keeps a stale render transform · Medium · New · Repro
- **Evidence:**
  - `UIElement.OnLiveTreeChanged` (`UIElement.cs:198-209`) re-applies the clip and marks the visual dirty, but never re-applies the transform.
  - `Arrange` short-circuits when the rect didn't change, so nothing else catches it.
- **Repro:** put a `Border` with a shared `TranslateTransform { X = 10 }` in a `StackPanel`. Remove it, set `X = 80`, re-add it, then lay out and render. `TransformToVisual(null)` still maps the origin to x = 100, not 170. A storyboard still running on an element removed mid-animation does exactly this.
- **Related (reviewer):**
  - The registration primitive (`ListenerList` + `ISubPropertyListener`) is wired by hand in about 30 places: 9 listener sets, 9 `OnLiveTreeChanged` overrides, and about 10 callbacks that move a registration.
  - Those places follow three lifetime rules:
    - elements listen only while live;
    - a geometry listens to its transform only while something listens to the geometry;
    - composites always listen to their children, so a child shared from code pins every parent that ever held it.
  - `group.Children.Add(group)` on a `TransformGroup` or `GeometryGroup` recurses until the stack overflows, which kills the process.
- **Recommendation:**
  - Re-apply the transform on attach, beside `ApplyClip()`, and add a remove / change / re-add test.
  - Then make registration declarative: a metadata flag ("tracks sub-object") that the DP store and `SetAttachedRoot` act on.
  - Use one base class for sub-property sources, with `Geometry`'s "listen to children only while heard" rule.
  - Add an ancestor check on insert.

#### R-11 · Removal and hot-reload rebuild leave focus, capture and running storyboards behind · Medium · New reachability (rebuild in live trees, #73) · Traced + Reviewer
- **Evidence:** when an element leaves the live tree, nothing releases `FocusManager.FocusedElement`, `InputManager`'s explicit and implicit capture, or its over-chains. The only release is `ReleaseDisabledFocus` (`FocusManager.cs:41`).
- **Consequence:** after rebuilding a view with a focused `TextBox`:
  - keys go to the detached box, and `WantsKeyboard` stays true;
  - its caret storyboard (`RepeatBehavior.Forever`) keeps running, because `StopCaretBlink` goes through `AttachedRoot?.Clock`, which is null once the box is detached (`TextBox.cs:224-228`);
  - the old tree stays alive, and `HasActiveClocks` stays true.
- **Other hot-reload gaps (reviewer):**
  - Rebuilding an inheritance view re-runs `InitializeComponent`, so root event handlers are wired twice.
  - `HotReload.ProcessPending` is global (`HotReload.cs:114-151`), so host A's `Tick` rebuilds host B's views on A's thread.
  - `HotReload.Enabled` is a settable property, not a feature switch, so ILC can't remove it. It is inert under NativeAOT rather than trimmed, as `docs/HotReload.md` says.
- **Recommendation:**
  - On leaving the live tree, release focus and capture held inside the subtree, prune over-chains, and stop clock entries whose targets left.
  - Keep a pending-rebuild set per host.
  - Wire root events outside the path that a rebuild re-runs.
  - Make `Enabled` a `[FeatureSwitchDefinition]`.

### Theme 3 — The §4 contract

#### R-12 · The generator silently ignores `x:` directives, Out-list ones included · High · Older (codified by this range) · Repro
- **Principle:** §4 says the generator "errors clearly on anything outside this grammar", and that Out forms "diagnose".
- **Evidence:** `XamlSourceGenerator.cs:389` skips every attribute in the `x:` namespace (`attrNs == X`), and the animation loops do the same.
- **Repro:** a view with `x:Uid="Greeting"`, `x:Phase="2"` and `x:Load="False"` builds with no diagnostic. The `x:Load="False"` element is loaded.
- **Why the tests miss it:** `XamlSubsetContractTests` (added in this range) has In and Planned tables but no Out table.
- **Recommendation:**
  - Allow only the `x:` names that are valid at each position (Class, Name, Key, DataType), and report the rest.
  - Add an Out table that asserts an error for each Out form.

  - The public `GlyphRunContent` now implies lines at the Unicode mandatory breaks, a line height apart, each aligned, with trailing whitespace hung. A foreign compositor must copy those rules by hand to match the measured layout.
  - `GlyphRunContent.TextAlignment` also puts a XAML enum on composition content, the R-16 pattern.
- **Recommendation:**
  - Add a public, allocation-free per-line read (glyph range, pen start, baseline) that `TextBlock`'s measure uses too.
  - Give composition content its own alignment enum.

#### R-35 · The new value forms have drifted from the §4 contract · Medium · New · Repro + Reviewer
- **`Width="Auto"`:**
  - It is In (§5 and `LayoutPropertyTests`), but absent from §4's Values paragraph and from `XamlSubsetContractTests`.
  - It lives only in the generator, so a `DiscreteObjectKeyFrame Value="Auto"` on `(FrameworkElement.Width)` is SUISEI012, and the runtime parser rejects it. That breaks §4's "a key's Value converts as a setter's does".
- **Non-finite durations.** **Repro:** `Duration="NaN"` reaches generated code as `TimeSpan.FromSeconds(NaN)`, and fails with CS0103 there instead of SUISEI012 at its XAML line. §4 says numbers "must be finite", and `TryParseDuration` also accepts infinite and negative values.
- **`Name=` on states:** §4 now publishes `Name=` on `VisualState` and `VisualStateGroup`. In WinUI those names are read-only and set by `x:Name` alone, so this is a SUIsei-only form on WinUI types.
- **Recommendation:**
  - Move the Auto rule into `XamlValueSyntax`, keyed by property, and add it to §4 and the contract test.
  - Reject non-finite and negative durations.
  - Report `Name=` on states.

#### R-36 · The whole test suite now runs with diagnostics on, so the configuration games ship with is untested · Low–Medium · New · Traced
- **Evidence:** `SUIsei.Tests.csproj:29` turns the switch on for the whole process, and `Enabled` can't change within a process.
- **What goes untested:** nothing checks the off path. That means the members that should throw, `RecordSource` doing nothing, and that no endpoint thread or pipe starts.
- **Side effects:**
  - Every allocation test now runs with diagnostics on, and every test run opens a pipe.
  - The earlier "ILC is clean" check of the test app no longer holds (R-25).
- **Recommendation:**

  - Add a NativeAOT smoke publish.

#### R-37 · Smaller items from #74 to #80 · Low · New · Traced + Reviewer
- **Absolute XAML paths are compiled into every view** (`XamlSourceGenerator.cs:562,570`, `Quote(gen.Path)`). A JIT build ships the developer's paths, and the output differs per checkout, since `/pathmap` doesn't touch string literals. Emit a path relative to the project.
- **`EnableDependentAnimation` coverage:**
  - It is on `DoubleAnimation`, `DoubleAnimationUsingKeyFrames` and `ObjectAnimationUsingKeyFrames`, but not `ColorAnimation` or `PointAnimation`, which WinUI has it on.
  - §5 lists only the first two.

- **`TextBox` hands its text to a `TextBlock` that now breaks lines,** while its caret math is single-line. Text containing a line break (bound, or typed U+2028 or U+0085) draws a second, clipped line the caret doesn't know about.
- **Inheritance coherence:**

  - `PassDown` indexes the live children list.
- **The tap reflects into the property system** (`TapEdits.cs:197`, `GetGenericArguments()[1]`; `:204`, `GetProperty("DefaultValue")`). `Diagnostics` should expose a property's value type and default.
- **`Diagnostics.TryParseValue` is a second converter table beside the generator's,** and already lacks `CornerRadius`, `Rect`, `Size`, `Geometry` and the collections.
- **`Planning.md:183` lists the value levels without BuiltInStyle.**

## What fits the principles well

- **Retained, versioned composition, allocation-free in practice:**
  - streams are double-buffered `RetainedBuffer`s, and list views come from a reused ring that throws on a stale read;
  - texture slots are one reference-keyed lookup;
  - `GradientSplitter` works on the stack, and `TessellatedPath.Emit<TSink>` uses struct sinks;
  - shaping and tessellation are cached on their content's `Version`;
  - tests prove each of these.
- **Sound texture lifetime:**
  - sources hold no host references, and `Dispose` only flips a volatile flag;
  - held counts settle at `EndRender`, so a source moving between surfaces in one render is kept;
  - it is covered by thread, GC and multi-surface tests.
- **A faithful oracle:** the rasterizer mirrors every kind, `Vector` included. It decodes sRGB before filtering, premultiplies straight alpha after it, and applies the top-left fill rule and the clip-centre rule.
- **A public, usable tessellator:**
  - a foreign compositor needs only `TessellatedPath.Emit<TSink>` with a struct `IVectorSink`, `VectorVertex` (which carries arc length) and `TessellationScale.For(Matrix3x2)`;
  - its antialiasing data matches §2 exactly: four distances, positive inside, `Unused` = 1e6;
  - joins and caps follow WinUI's semantics: miter limit in half thicknesses, dashes in thicknesses, dash caps on dash ends.
- **A genuinely typed, boxing-free DP store:**
  - writes, coercion on the resolved value, change checks and callbacks are all typed;
  - storyboard targets are compile-time `PropertyPath`s holding DP references, with no strings or reflection;
  - the animation-rung brush and transform paths replace July's `SetAnimated*` side channels (S-02, S-03).
- **A clean shaping seam:**
  - no HarfBuzz type reaches core;
  - `ITextShaper` takes `IGlyphSource` and an immutable, shared `FontFeatureSet`;
  - S-18 is resolved;
  - the glyph prim's `Custom.yz` clamps match §2 exactly, in the emitter and the oracle alike.
- **One converter table and shared parsing:**
  - the table covers every value position;
  - colour and path-markup parsing compile from one source into both the runtime and the netstandard2.0 generator;
  - S-26 (member types in the fingerprint) is fixed and tested;
  - `using:`, `suisei:` / SUISEI022 and `mc:Ignorable` match §4.
- **`Control.IsEnabled` follows WinUI's semantics:** inheritance, focus refusal, input suppressed while still bubbling, and hit-test blocking, with twelve focused tests.
- **The extensions rule was applied correctly where the range applied it:**
  - `ClipToBounds`, `WheelScrollAmount` and `RowHeight`;
  - the stroke extensions and `TextEffects`;
  - `Typography` in `SUIsei.Documents`, with WinUI's enum values.

**From #74 to #80:**
- **The precedence ladder is now WinUI's.** `Animation > Local > Template > Style > BuiltInStyle > Inherited > Default` matches WPF's documented order (Local > TemplatedParent > Style > default style > inheritance > default) and WinUI's. All seven rungs stay typed and boxing-free, and coercion still applies to the resolved value.
- **Field-backed layout DPs keep WinUI's dependency-property semantics at a plain field's cost.** They use AOT-safe `ref` accessors, a constructor guard that keeps "coercion on the resolved value" true by construction, and a test that the store and the field agree. A local set, a style added and removed, `ClearValue`, an animation and a tap edit were all traced as coherent.
- **#78's takeover model mirrors WinUI's handover between storyboards.** Its holding list is weak, pooled and allocation-free once warm, and tested for the empty state, the handover, the weak hold and allocation.
- **#79 turns no-allocation layout into a tested contract** across every panel, in 10 scenes (forced relayout, resize, animated size and margin, scrolling).
- **#76's object animation binds a typed write once and writes unboxed.** The eleven eases are pinned against reference curves.
- **Inheritance by push is built on the typed store's Inherited rung,** with WinUI's `ClearValue` semantics, and an equal value stops the push. Alignment is applied at emit with no layout and no allocation.
- **With the switch off, diagnostics cost nothing per frame.** The hot path gains one static-readonly check. Generated position records sit in one guarded block per `InitializeComponent` or factory. With the switch unset, ILC removes the guarded code; the reviewer checked this with a NativeAOT replica.
- **The tap is a proper satellite.** It reaches SUIsei only through the public `Diagnostics` API, and its overlay draws through the existing neutral path with no new prim kind.

## Suggested order

0. **R-25 first.** It is a one-attribute move and a catch-all on one thread, and it stops an opted-in NativeAOT game from being killed through its pipe. Then decide where the endpoint lives (R-26, R-27) before a game ships with it.
1. **Stop the per-frame path from throwing or going stale.** These are what a game sees as freezes, stuck input and flicker, and each is small. None was touched by #74 to #80.
   - R-01: make tweens write the Animation rung.
   - R-02: check at entry, degrade at draw, and make `Render` exception-safe.
   - R-03 and R-04: record the cache key in `Finish`, degrade past `MaxDashes`, and bound the dash walk.
   - R-05: route `CornerRadius` through `Validate`.
   - R-06: treat font range as a clamp, not a throw.
2. **Finish making WinUI visual states and templates work as written.** #78 and the `x:Name` fix did most of R-08 and R-13. What remains decides whether a template authored for WinUI behaves:
   - R-29: unwire a replaced template, then delete `RestoreBackground`;
   - R-30: make `Begin` all-or-nothing;
   - R-09: re-resolve paths;
   - R-31: put template values on the Template rung;
   - R-32: built-in controls shouldn't inherit a page's text.
3. **Tighten the contract test so drift can't recur.** Add an Out table, and fail on attributes and children the generator didn't consume (R-12, R-14, R-15, R-35).
